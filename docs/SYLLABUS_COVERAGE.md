## Common viva topics, quick answers

- **Why an API gateway?** One entry point; clients do not know service locations; login and role rules are enforced once.
- **Why service discovery?** Instances change address; Eureka lets `lb://book-service` resolve at call time.
- **What must a circuit breaker count?** Only server errors and timeouts. Counting business rejections (409) opened it wrongly (defect D6 in the report).
- **How is a loan kept consistent with the stock?** Saga: PENDING, keyed reservation, ISSUED plus outbox row in one transaction; compensation if the last step fails; recovery job for unknown outcomes.
- **Why an outbox?** Publishing after commit can lose the event if the broker is down; the outbox row is committed with the loan and relayed later (at least once), consumers deduplicate.
- **How do you follow one request?** Zipkin shows a trace across gateway, lending, member and book; the trace id is in every log line.
