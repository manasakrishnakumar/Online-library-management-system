# Design Document (SEED(S) Process)

## 1. Team topology

| Team | Type | Owns |
|---|---|---|
| Catalogue team | Stream-aligned | book-service |
| Membership team | Stream-aligned | member-service |
| Circulation team | Stream-aligned | lending-service, fine-service, notification-service |
| Platform team | Platform | api-gateway, discovery-server, config-server, Docker/K8s/CI, monitoring |

## 2. Actors

- **Member** - searches books, sees own loans, fines and notifications.
- **Librarian** - manages catalogue and members, issues and receives books, handles fines.
- **Administrator** - configures loan period and fine rate (Config Server).

## 3. Jobs to be done

| Actor | Job |
|---|---|
| Member | Find a book I want to read |
| Member | See what I borrowed and when it is due; know if I owe a fine |
| Librarian | Keep catalogue and members correct |
| Librarian | Issue and take back books quickly and without mistakes |
| Librarian | See overdue loans and unpaid fines |

## 4. Interaction: issuing a book (saga)

```
Librarian -> Gateway: POST /api/loans/issue + JWT           (token and role checked)
Gateway -> Lending
Lending: save Loan PENDING + LoanEvent LOAN_REQUESTED
Lending -> Member: GET /api/members/{id}                    (must be active)
Lending -> Book:   PUT /api/books/{id}/borrow, Idempotency-Key loan-{id}-borrow
Lending: one transaction: Loan ISSUED + LoanEvent BOOK_ISSUED + OutboxEvent loan.issued
Lending -> Librarian: 201 Loan            (202 if book-service did not answer; recovery job finishes it)
Outbox relay -> RabbitMQ -> fine-service, notification-service (asynchronous, at least once)
```

Failure paths: a 4xx from book-service fails the loan; an unknown outcome leaves it PENDING (202) and the recovery job replays the keyed step; if the last transaction fails, the reserved copy is released with key `loan-{id}-compensate`.

## 5. Actions and queries (API specification)

The OpenAPI 3 document of every service is generated by springdoc and saved in [openapi/](openapi) (26 operations); Swagger UI is on each service at `/swagger-ui.html`. The gateway additionally serves `POST /api/auth/login`.

| Type | Operations |
|---|---|
| Query | list/search/get books; list/get members; list loans, loans by member, loan history; list fines, fines by member; list notifications, by member |
| Action | add/update/delete book; register/update/delete member; issue loan, return loan, simulate overdue (demo); calculate fine, pay fine |
| Internal action | reserve / release a copy (`borrow`, `return`), idempotent, blocked at the gateway |

## 6. Event storming

`Book Added` -> `Member Registered` -> *Issue Book* -> `Loan Requested` -> `Book Issued` (or `Loan Failed`) -> *Return Book* -> `Book Returned` -> `Fine Assessed` -> `Member Notified` -> *Pay Fine* -> `Fine Paid`

Aggregates: Book, Member, Loan, Fine, Notification, which cluster into five bounded contexts.

## 7. Boundaries and sizing

| Bounded context | Service | Reason to change | Data owned |
|---|---|---|---|
| Catalogue | book-service | Cataloguing rules, copies | Book, StockOp |
| Membership | member-service | Registration rules, personal data | Member |
| Lending | lending-service | Loan rules, loan period | Loan, LoanEvent, OutboxEvent |
| Fines | fine-service | Fine policy and rates | Fine |
| Notifications | notification-service | Message wording and channels | Notification |

Module sizes (118 to 534 lines for the business services) are in the report.

## 8. Data and consistency

- One PostgreSQL database and one login per service; only IDs and small snapshots (book title, member name) cross boundaries.
- `LoanEvent` is an append-only log (light event sourcing); its read endpoint is the query side.
- Saga, idempotency keys, transactional outbox and idempotent consumers replace a distributed transaction (see section 4). Remaining limits: the outbox relay polls every 300 ms without publisher confirms, a PENDING loan has no retry limit, and the relay has only been tested with one lending instance.

## 9. Security

JWT (HS256, 60 min) issued by the gateway; role rules in `AccessRules` (librarian: everything public; member: browse catalogue and own loans, fines, notifications). Stock endpoints are internal. Demo users and secrets are configuration values for local use only.

## 10. Infrastructure, observability and release

- Config Server holds shared settings (loan period, fine rate, tracing and metrics settings); Eureka registers services; the gateway routes with `lb://`.
- Resilience4j circuit breakers count only server errors, connection errors and timeouts; Feign timeouts are 2 s connect and 3 s read.
- Zipkin traces (Micrometer Tracing, propagated through Feign and RabbitMQ), Prometheus metrics (including business counters) and a provisioned Grafana dashboard.
- One multi-stage Dockerfile, `docker-compose.yml` (14 containers), `k8s/library.yaml`, GitHub Actions workflow.
